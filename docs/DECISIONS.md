# Journal des décisions — Photogramme

- **2026-10-06** — Tauri 2 + React/TS ; FFmpeg/ffprobe en sidecar (exécutables séparés, build LGPL BtbN). Migration vers libav lié seulement si les mesures l'exigent.
- **2026-10-06** — Cible : films finis en H.264 8 bits 4:2:0 sous Windows. Pas de rushs, pas de LUT.
- **2026-10-06** — Encodage JPEG via `jpeg-encoder` (pur Rust, SIMD) au lieu de libjpeg-turbo : même échelle 1–100 et même contrôle du chroma, sans CMake/NASM à installer. À revoir si l'export en lot s'avère trop lent.
- **2026-10-06** — Capture à l'unité décodée sur CPU (l'initialisation du NVDEC coûte plus que le décodage d'une image). NVDEC réservé aux passes d'analyse sur le film entier (sprint 2).
- **2026-10-06** — Conversion YUV→RVB avec matrice explicite (BT.709 supposée pour la HD non taguée) pour des couleurs et des palettes justes.
- **2026-10-06** — Logique métier isolée dans le crate `photogramme-core` (sans Tauri), testée avec un vrai FFmpeg ; la couche Tauri ne fait qu'orchestrer.
- **2026-10-06** — Sécurité : scope asset vide par défaut, ouvert fichier par fichier ; aucune permission shell côté interface.
- **2026-10-06** — Correctif : `Command::output()` de tauri-plugin-shell 2.4.0 ajoute un 0x0A après chaque morceau de 8 Kio, même en `raw_out` (+3 038 octets sur une image 4K). La sortie est désormais collectée via `spawn()` (fonction `run_raw`), avec un test de non-régression sur une vraie image UHD. Le même défaut pouvait aussi altérer le JSON de ffprobe.
- **2026-10-06** — Panneau « Export JPEG » placé au-dessus des captures pour rester visible.
- **2026-10-06** — Interface en anglais uniquement (demande de l'utilisateur), nom « Photogramme » conservé. Commentaires du code et journal restent en français.
- **2026-10-06** — Détection des plans : une seule passe sur le film entier (NVDEC → `scale_cuda` 480 px → `hwdownload` → `scdet` → vignette 160 px). `metadata=print` écrit le score de CHAQUE image sur stderr (`pipe:2`, `direct=1`) ; les vignettes RVB sortent sur stdout. Le seuil est appliqué en Rust avec la règle de `scdet` (`score >= seuil`) : réglable en direct sans réanalyser. Durée minimale de plan ajoutée contre les flashs.
- **2026-10-06** — La même passe produit les vignettes (1/s + débuts de plan potentiels dès un score de 3, JPEG en mémoire servi par le protocole `thumb://`) et les colonnes du code-barre (moyenne de chaque ligne). Aucun fichier temporaire.
- **2026-10-06** — Décodeur d'analyse « Auto » : GPU si le fichier est compatible NVDEC, repli automatique sur le processeur en cas d'échec, raison affichée. « GPU » forcé : pas de repli.
- **2026-10-06** — Export en lot : images groupées (écart ≤ 3 s, 100 max par groupe), un seek par groupe + filtre `select`, 2 FFmpeg en parallèle, décodage processeur (comme la capture à l'unité). Précision vérifiée octet par octet contre un décodage séquentiel complet.
- **2026-10-06** — Export en lot : sortie lue image par image directement dans le tube (`From<Command> for std::process::Command` du plugin shell + `shared_child`), car le plugin plafonne à ~500 Mo/s en release (morceaux de 8 Kio). Gain mesuré ×4. Le plugin reste utilisé pour la sonde, la capture à l'unité et l'analyse. Jamais `output()`.
- **2026-10-06** — Palette : k-means++ dans CIELAB, graine fixe (déterministe), 40 000 points max, bandes noires ignorées. Calculée en Rust, dessinée par l'interface.
- **2026-10-06** — Code-barre : moyennes en lumière linéaire, deux styles (structure verticale / couleur unie).
- **2026-10-06** — Overlay : composition Canvas (fonction `render` unique pour l'aperçu et l'export, mêmes pixels RVBA exacts fournis par FFmpeg, contexte `willReadFrequently` = rendu logiciel identique). Encodage JPEG en Rust pour garder qualité et chroma. Tailles en « px base 1920 ». Préréglages JSON validés et bornés côté Rust.
- **2026-10-06** — Transferts d'images interface ↔ Rust en binaire (paquet en-tête JSON + RVBA, `ipc::Response` / corps brut), jamais en JSON.
- **2026-10-06** — Sécurité : sélecteurs de fichier/dossier ouverts côté Rust. La commande JS `open` de tauri-plugin-dialog 2.8.1 ouvrait le scope asset RÉCURSIVEMENT sur le dossier choisi ; l'API Rust ne touche à aucun scope. Permission `dialog:allow-open` retirée : l'interface n'a plus que `core:default`. L'interface n'envoie jamais de chemin d'écriture.
- **2026-10-06** — CSV d'export : UTF-8 avec BOM, séparateur « ; » (Excel français), champs commençant par = + - @ neutralisés (injection de formule).
- **2026-10-06** — Scripts PowerShell en UTF-8 avec BOM et fins de ligne CRLF (PowerShell 5.1). Les tests d'intégration encodent leurs vidéos en libopenh264 si libx264 est absent (build LGPL).
- **2026-10-06** — Correctif `cargo test` sous Windows (0xc0000139, STATUS_ENTRYPOINT_NOT_FOUND) : le plugin dialog importe `TaskDialogIndirect` (Common Controls v6), qui exige un manifeste ; tauri-build ne l'embarque que dans l'exécutable de l'appli. Le manifeste (`src-tauri/windows-app-manifest.xml`, copie de celui de tauri-build) est désormais embarqué par l'éditeur de liens dans tous les exécutables (`/MANIFEST:EMBED` + `/MANIFESTINPUT`), comme le fait le build.rs de Tauri pour ses propres tests ; la ressource n'en contient plus (`new_without_app_manifest`) pour éviter un doublon.
- **2026-10-07** — v0.4 : audit puis correctifs d'exactitude avant toute fonction nouvelle.
- **2026-10-07** — Pixels non carrés : la sonde lit le SAR ; tout photogramme est remis au rapport d'affichage (lanczos), largeur corrigée. Rotation (téléphones) : FFmpeg lancé avec `-noautorotate` partout, rotation appliquée par nos filtres après conversion en RVB (90 → `transpose=cclock`, 270 → `transpose=clock`, 180 → double miroir), conventions vérifiées contre la rotation automatique de FFmpeg 8.1 (écart moyen 0,01/255). Raison : la rotation automatique insère un filtre qui échoue sur des images restées en mémoire GPU.
- **2026-10-07** — Timecode : départ lu dans le fichier (flux vidéo, piste `tmcd`, conteneur) + drop-frame 29,97/59,94 (SMPTE ST 12-1). Réglage « From the file / From 00:00:00:00 ». Même algorithme en Rust et en TypeScript, mêmes vecteurs de test.
- **2026-10-07** — Début décalé (`start_time` ≠ 0) : capture FFmpeg vérifiée image par image contre un décodage séquentiel. Côté visionneuse (WebView2), contrôle automatique sur une image arrêtée : comparaison de l'image affichée aux images N−1, N, N+1 de FFmpeg ; décalage corrigé s'il est net, rien sinon (plan fixe). La balise <video> passe en `crossOrigin` (le protocole asset renvoie l'en-tête CORS) ; repli automatique sans `crossOrigin` si le chargement échoue.
- **2026-10-07** — Import des coupes : EDL CMX 3600, OTIO, FCP 7 XML, FCPXML. Calage par le timecode du fichier ; si la majorité des coupes tombe hors du film, alignement du début de la timeline sur la première image (avertissement). Cadences différentes : conversion par le temps, avertissement. XML lus sans DTD (roxmltree, `allow_dtd: false`).
- **2026-10-07** — Coupes à la main (B) envoyées au Rust avec la liste : vignettes et images retenues calculées au même endroit que les coupes détectées. Une coupe fusionnée puis recoupée est rétablie.
- **2026-10-07** — Export PNG (crate `png`, déjà compilé pour Tauri) et profils ICC v2 générés en Rust (Rec.709/BT.1886 γ2,4, sRGB), validés par LittleCMS. « Convert to sRGB » : conversion γ2,4 → sRGB à luminance égale, appliquée AVANT composition et palette, pour que pastilles, aperçu et fichier concordent.
- **2026-10-07** — Palette « accents » : k-means pondéré par la chroma (poids 1 + (C*/25)², plafonné à 12) ; la part affichée reste une part de surface. Export ASE/CSS/GPL/JSON.
- **2026-10-07** — Scopes (forme d'onde, parade, vectorscope, histogramme) calculés sur les pixels exacts, composés pixel par pixel : identiques dans le panneau, l'aperçu et l'image exportée. Vectorscope BT.709, cibles 75 %, axe I à 123°.
- **2026-10-07** — Planche contact : mise en page Canvas (même moteur que l'overlay), images décodées par FFmpeg à la largeur exacte d'une case et posées sans mise à l'échelle. PDF écrit sans bibliothèque (une page = un JPEG en DCTDecode), validé par qpdf et pdfium.
- **2026-10-07** — Glisser-déposer capté en Rust (`WindowEvent::DragDrop`) : l'interface n'envoie plus aucun chemin de fichier. Liens externes (dépôt, Ko-fi) fixés en Rust.
- **2026-10-07** — Mises à jour : tauri-plugin-updater appelé côté Rust uniquement (aucune permission ajoutée à l'interface), `requireSignedVersion` (pas de retour forcé à une version plus ancienne), plugin enregistré seulement si une clé publique est compilée. latest.json produit par la CI. Signature de code Windows reportée (Azure Trusted Signing fermé aux particuliers hors USA/Canada ; SignPath Foundation ou Certum Open Source envisageables plus tard).
- **2026-10-07** — FFmpeg épinglé : archive copiée dans la release `ffmpeg-deps` du dépôt (pré-release, jamais « latest »), adresse + SHA-256 + commit dans `scripts/ffmpeg.lock`. Raison : les builds « latest » de BtbN changent chaque jour et les anciens disparaissent.
- **2026-10-07** — Release par GitHub Actions (Windows) sur tag vX.Y.Z, brouillon publié à la main (`scripts/release.ps1` tape PUBLISH). Couche Tauri découpée en modules (film, frames, shots_cmd, batch_cmd, app_cmd, state).
- **2026-10-07** — Limites connues : rien n'est révoqué dans le scope asset à la fermeture d'un film (l'API ne sait qu'interdire définitivement) ; installeur non signé (SmartScreen).
- **2026-10-08** — Ratio de l'image : règle absolue, l'image du film n'est jamais déformée, ni à l'export ni à l'écran. Export : copie 1:1 (`putImageData`), vérifiée pixel à pixel. Écran : tout canvas qui affiche une image a `object-fit: contain` (le navigateur garde le ratio même si la boîte a un rendu de retard) et la boîte « fit » est recalculée dans le même rendu que le ratio (`fitBox`, pure). Raison : la boîte suivait le nouveau ratio un à deux rendus après le canvas → image étirée jusqu'à 16 % à chaque changement de préréglage, en continu pendant le réglage des marges. Référence A/B posée sur la zone image de la composition.
- **2026-10-08** — Version macOS : Apple Silicon seulement (aarch64-apple-darwin), macOS 12+. Intel écarté pour l'instant : un second FFmpeg, un second build et des runners Intel en fin de vie pour un parc qui disparaît.
- **2026-10-08** — GPU sur Mac : VideoToolbox (`-hwaccel videotoolbox`), images rapatriées par FFmpeg puis même réduction et mêmes filtres que sur processeur. Pas de `scale_vt` tant qu'il n'est pas mesuré sur une vraie machine : sur Apple Silicon la mémoire est unifiée, le rapatriement est une simple copie. Même règle de compatibilité que NVDEC (H.264 8 bits 4:2:0, HEVC 8/10 bits 4:2:0). Le champ `nvdec_compatible` garde son nom (projets en cache) et veut dire « décodable par le GPU ».
- **2026-10-08** — FFmpeg Mac compilé par `scripts/build-ffmpeg-macos.sh` depuis le commit épinglé dans `scripts/ffmpeg.lock` (même version que Windows, source déjà jointe aux releases) : LGPL v3, aucune bibliothèque externe, pkg-config neutralisé contre Homebrew, réseau désactivé, contrôle `otool` (bibliothèques système seulement). Notices propres au Mac générées par le script et substituées dans le paquet par `tauri.macos.conf.json`.
- **2026-10-08** — Signature Mac : ad hoc (`signingIdentity: "-"`), pas de notarisation (compte Apple Developer payant). Premier lancement : Réglages Système > Confidentialité et sécurité > Ouvrir quand même. Mises à jour : `latest.json` unique avec `darwin-aarch64` (archive .app.tar.gz signée minisign).
- **2026-10-08** — Interface : raccourcis ⌘ sur Mac (Ctrl sous Windows), Option+X lu par la touche physique (`e.code`), libellés GPU/Finder et polices proposées selon la plateforme (`src/platform.ts`, lue dans l'agent utilisateur de la WebView, sans permission en plus).
- **2026-10-09** — Interface v0.7 : quatre onglets d'inspecteur (EXTRACT / GALLERY / LOOK / OUTPUT) au lieu de trois, réglages d'application dans une fenêtre Preferences (Ctrl+,), palette de commandes (Ctrl+K, ~70 commandes, recherche sans accents, chaque mot doit correspondre) et aide des raccourcis (?). Inspiration DaVinci Resolve (panneaux sur gouttière sombre, en-tête de visionneuse avec timecode) et Figma (calques du LOOK avec œil). Raison : divulgation progressive (Nielsen) et passage novice → expert par la palette (Cockburn, Gutwin & Greenberg, CHI 2007). Anciens onglets enregistrés (« captures », « settings ») convertis à la lecture du projet.
- **2026-10-09** — Skins Studio (sombre/clair), Atomic (sombre) et Mission (clair) : un skin ne change QUE des jetons CSS (`:root[data-skin]`), jamais la police du corps ni la mise en page ; Atomic et Mission imposent leur thème. La visionneuse (#151515 / #000) et les scopes restent neutres dans tous les skins (entourage neutre, esprit SMPTE ST 2080-3). Décorations (barres de couleur, pointillés, trame) coupables par « Skin decoration ». Polices ajoutées, toutes SIL OFL 1.1 et embarquées : Instrument Sans, Space Mono, Archivo. Contrastes WCAG vérifiés par les tests pour les quatre apparences.
- **2026-10-09** — Réglage `ui.skin` lu avec tolérance côté Rust (`deserialize_with`) : valeur inconnue (version future, fichier édité) → Studio, au lieu de rejeter tout le fichier de réglages.
- **2026-10-09** — Raccourcis clavier : bloqués seulement dans un champ de saisie, une liste ou une zone de texte ; sur une case à cocher seule l'Espace est gardé, sur un curseur seules les flèches et Home/End/PageUp/PageDown (`src/keys.ts`, testé). Corrige un défaut v0.6 : un clic sur une case ou la timeline coupait tous les raccourcis. Aucun raccourci quand une fenêtre (dialog) est ouverte.
- **2026-10-09** — Effets FFmpeg déclenchés par des clés ciblées (`frameKey` : palette, couleur, timecode ; `pickKey` : choix des images par plan) au lieu d'un compteur de version des réglages. Raison : en v0.6, chaque retouche de l'overlay relançait grab_frame et list_shots.
- **2026-10-09** — Fenêtres (Preferences, palette, raccourcis) pilotées par l'état de l'application : `onCancel` annulé puis fermeture par l'état, `onClose` resynchronise. L'événement `close` du navigateur est différé : il n'est pris en compte que si la fenêtre est réellement fermée (sinon une réouverture rapide, Ctrl+K juste après une commande, était refermée par l'événement de la fermeture précédente). À la fermeture, la fenêtre rend le clavier (`blur`) et la palette vide sa recherche ; une touche qui vise un élément d'une fenêtre fermée n'est pas une saisie (`shortcutBlocked`). Raisons, mesurées par les tests en enchaînant les commandes : Échap puis réouverture immédiate laissait l'état faux ; le champ caché gardait le clavier jusqu'au rendu suivant (Ctrl+K perdu) ; la recherche précédente se collait à la nouvelle.
- **2026-10-09** — Tests d'interface Playwright (`npm run test:e2e`, job CI `interface`) sur l'interface réelle avec un faux backend Tauri (`e2e/mock-tauri.js`) : 4 apparences × 3 tailles × 4 onglets (débordements, contrastes, noms accessibles), visionneuse, extraction, look, sortie, préférences, toutes les commandes de la palette. Plus un test de l'application compilée (tauri-driver + WebKitWebDriver, `e2e/real-app.mjs`, Linux) avec un vrai FFmpeg : capture, détection, exports, PDF, palettes, skin enregistré, redémarrage. Limite : WebView2 (Windows) et WKWebView (Mac) ne sont pas couverts par ce test réel.
- **2026-10-09** — Scripts de release : la ligne de licence vit dans `src/PrefsDialog.tsx` (Preferences › About & licenses), sur une seule ligne gérée par `publish-public.ps1` ; `prepare-release.ps1` ne fait plus que la vérifier (plus aucune injection de code).
- **2026-10-09** — Lecteur : les rappels `requestVideoFrameCallback` reçus pendant un déplacement (`video.seeking`) sont ignorés ; `seek` pose déjà le numéro visé. Raison (défaut présent en v0.6, mesuré : jusqu'à 3 retours en arrière sur 150 pas sous charge) : un rappel en route décrivait l'image d'avant, le numéro revenait un instant à N, et un I, O ou C tapé à ce moment visait la mauvaise image. Repères de la timeline dédoublonnés (deux captures de la même image donnaient deux clés React identiques).
- **2026-10-09** — Tests d'interface : aucune erreur de console ou de page tolérée, contrôlée automatiquement après chaque test (fixture `cleanConsole` de `e2e/helpers.ts`), pas seulement dans les tests qui y pensent.
